# P45 — Historical decoder recovery: handler provenance and turn/Ready research

**Release:** 21 October 2026. **Baseline:** complete P44. **Scope:** OFFLINE / RESEARCH ONLY. The original R5.198 and the prior P44 archive remain unmodified. This work does not certify or enable current-client protocol, Canonical admission, Windows interaction, or autonomous gameplay.

## Why this was the highest-value next reuse step

P44 recovered real Unity map-projection *source*. The next major R5.198 resource is its version-local Dofus **3.7.10.10** wire-to-Canonical handler knowledge. Blindly copying the old live decoder into ANKA_NEXT would reintroduce runtime dependencies (`anka_platform`, canonical domain classes and handler state) and could mistake historic data for current-build authority. P45 therefore makes the old mapping searchable and reproducible **without importing it**, while extracting a small, useful, strictly bounded part into a new research-only implementation.

## What was recovered

`reference/protocol/historical_3_7_10_10/` contains **seven archived R5.198 reference assets** as inert `.source.txt` files, with original relative paths, content sizes and SHA-256 checksums in `handler_inventory.json`. The latter indexes **39 historical handler bindings in five capability groups**: `world_identity`, `fight_state`, `resources_effects`, `combat_actions`, and `fight_lifecycle`. The inventory was generated by a Python AST inspection of the old `handler_modules/registry.py` without importing or running any old code. The inventory itself has a pinned SHA-256 enforced by `anka_protocol.historical_lineage`.

This is historic **research provenance**, not 39 functioning new adapters and not proof of a current protocol version. Tampering with source, manifest or symlinked source directories fails the normal `check`/`setup`/`start` preflight before any gameplay authority can exist.

## New independent lifecycle decoder

`anka_protocol.adapters.historical_lifecycle.HistoricalLifecycleDecoder` is a separate *pure* historical research decoder using the existing strict `WireMessage`, `parse_fields` and `EvidenceRef` contracts. It only recognizes the **historically documented** Dofus 3.7.10.10 server messages listed here:

| Old wire name | Historical field numbers | Research output |
|---|---|---|
| `jvi` | `1 = round` | `ROUND_OBSERVED` |
| `jvj` | `3 = signed active actor`, optional `6 = wire turn index`, optional `7 = round` | `TURN_OWNER_OBSERVED` |
| `jup` | `2 = signed actor` | `TURN_END_OBSERVED` |
| `jxd` | `2 = signed actor`, `3 = ready (exact 0/1)` | `FIGHT_READY_OBSERVED` |

The mappings are checked against `handler_modules/fight.py` in R5.198. For this **conservative research projection**, missing optional `jvj` fields remain `None` instead of inheriting an inferred actor/round/index. Missing required fields, duplicate scalars, malformed wire data, impossible values and non-binary Ready are quarantined.

### Scope and consequence of uncertainty

- `requested_build` must equal `Dofus 3.7.10.10`. A newer build returns `BUILD_MISMATCH`.
- `LegacyFightScope` must explicitly provide a positive caller-supplied fight ID, pinned historical build, flow digest and TCP generation. Decode refuses any empty or mismatched flow. **The scope is an offline assumption**, not a verified identity binding or authorization.
- Client-to-server messages are not accepted as server Ready/turn truth. All data is `HISTORICAL_RESEARCH_ONLY` with explicit original packet/generation/message offsets; no raw IP, account name or packet body is placed in a public report.
- `anka_protocol.historical_timeline.audit_historical_timeline` analyzes **only one flow/fight/build/generation at a time**. It flags reordered or duplicated sources, owner switch without End Turn, End Turn for the wrong actor and missing owner proof. It never merges CRA and ENU socket timestamps into an invented global turn order.
- `LegacyFightResult` and `LegacyTimelineReport` carry no action authorization and report zero Canonical commits/physical inputs. No API in this release promotes these observations to admitted events. `anka_execution` and `anka_live_state` were not changed.
